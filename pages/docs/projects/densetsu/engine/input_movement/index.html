Overview

The current player-control path is explicit enough to document directly. Input actions live in project.godot, are named centrally in PlayerInputActions.gd, are resolved into a command frame by PlayerCommandResolver3D, and are consumed by the active actor and motor stack.

Current Input Reality

  • Canonical labels: the active label list is documented in docs/player_input_reference.md and mirrored in engine3d/controllers/PlayerInputActions.gd.
  • Command frame: PlayerCommandFrame3D is the runtime handoff object for locomotion, combat, posture, camera, and edge-trigger signals.
  • Current cleanup state: block and weapon_toggle exist in code and input map but remain intentionally unbound by default.
  • Locomotion caveat: sneak is currently an input alias for crouch or duck-walk, not a separate locomotion family on the active player path.
  • Known ambiguity: ledge_grab_held is still derived from the modifier path rather than being its own first-class label.

Pages

  • Input Overview - action families, command-frame mapping, and current binding rules.
  • Movement Controller - movement-state resolution and controller flow.

Status

Implemented and being tightened. The input surface is no longer vague, but the docs and code still show migration seams around control layout finalization, ledge-grab intent, and how closely locomotion states should mirror authored animation slots.
