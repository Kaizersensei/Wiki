This page documents the canonical label surface for the active shell or motor runtime path. It is intentionally narrower than a general control-guide page: the goal here is to keep the engine-side action labels, command-frame fields, and current binding rules aligned.

Pipeline

  1. project.godot defines the input actions that exist in the project.
  2. PlayerInputActions.gd names the canonical labels used by runtime code.
  3. PlayerInputSource.gd reads the live input map.
  4. PlayerCommandResolver3D.gd resolves live input into a PlayerCommandFrame3D.
  5. The active actor or motor path consumes the command frame through shell or component boundaries.

Command Frame Mapping

  • The command frame carries movement vectors, jump and modifier edges, attack intent, posture intent, camera toggles, and derived gesture helpers.
  • ledge_grab_held is currently derived from the modifier path rather than being its own project input action.
  • sneak_held is still preserved at input level for compatibility even though the active locomotion path collapses it into crouch-family behavior.

Binding Rules

  • Add every supported player action label to project.godot even if it remains temporarily unbound.
  • Keep PlayerInputActions.gd and the input reference document in sync when labels are introduced, repurposed, or retired.
  • Do not let fallback-only labels become silent shipping behavior.

Open Cleanup Items
