This page is the current inventory for the engine wiki overhaul, not a subsystem reference by itself. Its job is to keep the audit honest: what repo truths are already verified, which wiki sections were corrected in the current pass, and which remaining areas still need a code-first rewrite instead of placeholder copy.

Documentation Standards For The Current Wave

  • Every page should open with explicit metadata: page type, audience, implementation status, last verified date, and repo-local source inputs.
  • Current implementation, target architecture, and known drift must stay visually separate so design notes are not mistaken for live behavior.
  • Prefer repo-local code, config, and docs over older scan summaries or external-path references.
  • Use tables for contracts, dependencies, schema surfaces, and ownership boundaries; use callouts for risk, migration state, and operational blockers.
  • When the repo is incomplete, say so directly. Missing assets, placeholder modules, and compatibility layers should be documented as limits, not inferred away.
  • Track missing diagrams or screenshots explicitly, but do not let absent media block text corrections.

What Not To Document One File At A Time

  • Imported raw assets, generated metadata files, and unmodified upstream addon internals.
  • Backup, broken, temp, and recovery scenes except where a cleanup or archival policy is the real topic.
  • Every demo or test asset instance when a workflow page or scene-purpose map would communicate more clearly.
