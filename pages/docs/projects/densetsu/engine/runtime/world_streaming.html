The live runtime tree does not currently expose a standalone chunk-streaming or region-streaming service. What it does expose is a project-owned world facade layer that resolves terrain, water, and sky/weather from the active scene so runtime systems can stop depending directly on plugin-specific node assumptions.

Current World Runtime Surface

Surface Current role
WorldFacadeServiceAutoload that refreshes against the active scene, builds facade snapshots, and publishes facades_refreshed(scene_root).
TerrainFacade3DThin project-owned wrapper over Terrain3D discovery, height queries, region presence checks, and camera binding.
WaterSurfaceFacade3DController-level wrapper over project water surface and flowmap controllers.
SkyWeatherFacade3DProject-owned boundary for sky system, clock resolution, weather selection, and calendar/weather snapshots.
RuntimeCalendarServiceConsumes world facade data and republishes normalized calendar and weather presentation state.
Terrain3DRuntimeCollisionBridgeCompatibility autoload that now prefers terrain facades for camera binding but still keeps the old direct fallback.

Validated Runtime Behavior

  • smoke_world_facades.tscn validates that WorldFacadeService loads and resolves sky/weather, water, and empty-root terrain behavior.
  • WorldFacadeService refreshes on tree changes instead of forcing every runtime consumer to re-scan the scene manually.
  • RuntimeCalendarService treats world facade output as the normalized input for time and weather presentation.

What This Is Not

Expectation Current repository truth
Dedicated world streaming serviceNo WorldStreamingService or equivalent runtime autoload is present.
Chunked runtime loaderNo live runtime code in this tree manages chunk lifetime, region streaming, or streaming budgets as a first-class system.
Biome compiler at runtimedocs/biome-driven maps.md keeps SQLite and compilation in the editor/tooling path; runtime is expected to consume compiled outputs later, not query SQLite directly.
Completed world facade migrationThe worklog still labels terrain coverage backend-only, water coverage controller-level, and the collision bridge as a compatibility layer.
