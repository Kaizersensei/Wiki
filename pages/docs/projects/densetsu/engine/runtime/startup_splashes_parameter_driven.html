DensetsuSplashScreen is the reusable splash primitive behind the current startup splash presets. The script exposes node paths, timing, text, visuals, and skip behavior as parameters so multiple branded or informational splash scenes can share one playback implementation.

Parameter-Driven Surface

Area Current parameters Role
Node bindingsRoot, background, logo, title, subtitle, and skip-hint node paths.Lets one script drive different splash scene layouts.
Playbackauto_play, allow_skip, skip_actions, skip_with_any_input, minimum_display_before_skip_secondsControls when and how input can interrupt playback.
Timingfade_in_seconds, hold_seconds, fade_out_seconds, skip_fade_out_secondsDefines the full splash cadence.
Visuals and textBackground color or texture, logo texture, title and subtitle text, tinting, and optional skip hint.Turns the primitive into project-specific presets without code duplication.

Playback Contract

  1. On _ready(), the script resolves its nodes, applies visuals, enables processing, and auto-plays at runtime when auto_play is enabled.
  2. play() resets internal state, arms skip timing if skipping is allowed, and fades the root control in.
  3. It waits for the configured hold period unless a valid skip event is accepted.
  4. It fades out using either the normal fade-out duration or the faster skip fade-out duration.
  5. It emits finished when playback is complete so callers can sequence the next splash or proceed into loading.

Skip Behavior

Concern Verified behavior
Default action-based skipskip_actions defaults to ui_accept, ui_cancel, and unarmed_action.
Broad input skipIf enabled, key, mouse, joypad-button, and screen-touch input can also skip.
Early-skip guardminimum_display_before_skip_seconds gates when skip becomes active.
Skip hint visibilityThe hint can be shown always or only once skipping is currently allowed.

Default Boot Usage

DensetsuBootLoader currently seeds startup_splash_scenes with DensetsuCompanyLogoSplash.tscn and DensetsuStartupInfoSplash.tscn. When splash playback is enabled, the bootloader instantiates each scene, forwards startup_splash_allow_skip into the splash instance, awaits its finished signal, and optionally waits for startup_splash_gap_seconds before moving to the next one.

Runtime Boundary

Verified distinction: these splash assets are part of the bootloader-controlled startup pipeline, not the current manifest-driven runtime bootstrap root.

Implication: document them as reusable presentation assets and bootloader presets, not as proof that the whole project still boots through the legacy loading scene.
