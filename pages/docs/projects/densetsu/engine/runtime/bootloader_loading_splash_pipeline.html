The current production runtime boots through res://engine3d/runtime/RuntimeBootstrap.tscn, not through DensetsuBootLoader. The bootloader pipeline is still real code and a valid launch asset, but it should be documented as a reusable direct-scene startup path rather than the authoritative project boot root.

Current Role

Concern Verified state
Primary runtime entryproject.godot points at RuntimeBootstrap.tscn.
Bootloader assetDensetsuBootLoader.gd remains a concrete loading-and-handoff scene controller.
Loading hostThe bootloader instantiates DensetsuLoadingScreen.tscn and configures its behavior before starting the load.
Splash playbackThe bootloader can play an ordered splash scene list before the loading screen appears.

Verified Sequence

  1. DensetsuBootLoader resolves a target scene from target_scene_path, optionally overridden by --scene=... or --scene ....
  2. If play_startup_splashes is enabled, it plays each configured splash scene in order and waits for each finished signal.
  3. It instantiates DensetsuLoadingScreen.tscn and pushes configuration into the instance, including auto-switch behavior, minimum visible time, overlay visibility, and optional content scene injection.
  4. It connects loading_started, loading_progress, loading_completed, and loading_failed for boot logging and failure visibility.
  5. It calls begin_load_scene(resolved_target) on the loading screen and lets that node own the actual load lifecycle.

Default Scene Wrapper

DensetsuBootLoader.tscn is a simple wrapper around the bootloader script and currently sets minimum_visible_seconds = 1.0. That makes it a ready-to-use launch scene for controlled flows, but it does not replace the manifest-driven runtime bootstrap path documented elsewhere.
