Core Runtime Overview

Purpose

The core runtime packages the systems that bring the game online: boot sequence, loading screen, scene activation, and the singleton services used throughout gameplay. Evidence is anchored in the bootloader, loading UI, scene manager, and autoload services recorded in the context database.

Responsibilities

  • Run the boot sequence and startup splash pipeline.
  • Expose loading progress and failure signals to UI.
  • Prepare and activate target scenes.
  • Provide global services (event bus, input manager, runtime context).

Data & interfaces

  • Resource-backed data sets (example resources: AIProfileData, BiomeData, CollisionData, FactionData, ItemData).
  • Runtime data assets in data3d/ (camera, items, prefabs).

Dependencies

  • Inbound: main.tscn, World.tscn, autoload singletons.
  • Outbound: loading screens, scene manager, input/controller modules.

Debugging & tooling

Use the loading screen signals and bootloader logging hooks to trace startup issues. Runtime services should be reachable through autoloads.

Constraints

  • Save/load and world streaming evidence not confirmed in the current context database.
  • Runtime dependencies should remain autoload-safe (no scene-only assumptions).
