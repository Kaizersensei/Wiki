DensetsuLoadingScreen is not just a static art screen. It is the reusable runtime host that owns content-scene instancing, overlay bindings, optional threaded scene loading, fallback behavior, completion signaling, and scene handoff timing.

Host Responsibilities

Layer Current role
Content hostInstantiates an arbitrary PackedScene under ContentRoot through content_scene, set_content_scene(), or add_content_node().
Overlay shellOwns rebinding for overlay canvas, loading panel, gauge, status label, and detail label through exported node paths.
Presentation layerApplies visibility, panel layout, style override, label styling, and gauge styling from exported properties.
Load driverStarts blocking or threaded scene load requests, polls progress, emits signals, and optionally changes to the loaded scene.
Diagnostics bridgeLogs to DiagnosticsService when that autoload is available.

Slot And Binding Surface

  • content_root_path defaults to ContentRoot and is the slot for arbitrary runtime content.
  • overlay_canvas_path, loading_panel_path, gauge_path, status_label_path, and detail_label_path let the scene remap its UI bindings without rewriting the script.
  • clear_content_before_instancing controls whether old content children are removed before new content is inserted.
  • Overlay visibility, panel size, bottom margin, style override, and label tinting are all exported, so the same script can host different presentation layouts.

Loading Behavior

  1. begin_load_scene(scene_path) normalizes the path, resets progress state, updates status text, and emits loading_started.
  2. If use_threaded_loading is disabled, it defers directly into blocking load mode.
  3. If threaded loading is enabled, it uses ResourceLoader.load_threaded_request(), polls status every frame, and emits loading_progress.
  4. If a threaded request errors or times out and fallback is enabled, it attempts a blocking ResourceLoader.load() path instead.
  5. On success, it stores the loaded PackedScene, emits loading_completed, and changes scene automatically once minimum_visible_seconds has elapsed if auto_switch_to_loaded_scene is enabled.

Signals And Extension Points

Signal Use
loading_started(scene_path)External boot or test harnesses can react when the load request begins.
loading_progress(scene_path, progress)Lets callers monitor or mirror progress without owning the poll loop.
loading_completed(scene_path, packed_scene)Provides a hook before or alongside automatic scene switching.
loading_failed(scene_path, reason)Surfaces user-visible or diagnostic failure reasons to the host pipeline.

Current Limitations

Concern Verified state
Threaded loading defaultuse_threaded_loading defaults to false, so threaded behavior must be enabled intentionally.
Dependency expectationDiagnostics logging is opportunistic; the script checks for /root/DiagnosticsService rather than assuming it always exists.
Content contractThe host accepts arbitrary scenes, but this page does not define any stronger content-scene API than normal Godot node composition.
