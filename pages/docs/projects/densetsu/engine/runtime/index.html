Overview

The active runtime no longer boots through an arbitrary gameplay scene. It starts in RuntimeBootstrap.tscn, validates runtime ownership through explicit services, resolves startup content through the runtime manifest and data catalog, and then hands scene activation to SceneFlowService.

Current Runtime Shape

  • Startup root: project.godot points to res://engine3d/runtime/RuntimeBootstrap.tscn.
  • Core authority: manifest, catalog, diagnostics, scene flow, presentation, and player-lookup services are autoloaded explicitly.
  • Diagnostics: runtime failures are meant to produce visible feedback and persistent traces instead of silent blank-screen failure.
  • Debug flow: editor runs default to scene-selector mode through run/main_run_args="--scene-selector".
  • Validation: runtime smoke scenes and export-manifest checks are part of the rewrite acceptance path.

Status

Implemented and still under rewrite. The deterministic boot path, runtime services, manifest or catalog authority, selector flow, and smoke gates are present. The documentation and code still show migration seams around full catalog coverage, headless reliability, and later runtime subsystems such as complete save/load and world streaming.
