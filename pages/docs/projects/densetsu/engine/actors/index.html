Overview

The actor stack is currently split between two truths. The production game still depends on the legacy ActorCharacter3D path, while the shell or component architecture exists in parallel as the migration target for player, NPC, enemy, and presentation ownership.

Current Architecture

  • Legacy authority: ActorCharacter3D.gd remains the runtime authority for the active gameplay path.
  • Player reality: ActorPlayer3D still extends the legacy actor root in production, even though shell-based player scenes and bridges exist.
  • Rewrite path: ActorShell3D plus components such as input, movement, combat, camera, animation, traversal, and state tags are live and used by shell scenes.
  • Service boundary: PlayerActorService is the current runtime-facing lookup layer that helps isolate the rest of the runtime from direct player-scene assumptions.

Status

Implemented and under rewrite. The legacy actor path is still authoritative, but shell scenes, typed components, and player-service boundaries are already present and should be treated as the migration direction rather than unused experiments.
