The framework idea is correct: creatures are supposed to live inside the actor architecture rather than as a separate gameplay species system. The important correction is scope. In the current repo snapshot, creature support is only partially on that path, and most animal content still rides the legacy actor stack.

What Is Verified

  • AnimalNPC3D.gd extends ActorNPC3D.gd, which means the current animal path is a specialization of the legacy NPC actor line.
  • The animal specialization in that script is animation-state auto-mapping and runtime retry logic around imported clips. It is not a shell-root replacement.
  • The animal templates currently found under engine3d/actors/templates/animals/ point at AnimalNPC3D.gd as their root script.
  • Humanoid shell scenes do exist, but they are not the same thing as a verified creature-wide shell framework.

How Creatures Fit Today

  • Creatures are part of the actor family in the sense that they reuse actor roots, movement, animation, and NPC runtime behavior rather than forming a separate engine subsystem.
  • For the live repo state, that mostly means legacy inheritance: animal scenes inherit the NPC line and keep the same broad lifecycle constraints as other monolith-backed actors.
  • The main creature-specific addition currently verified in code is animation adaptation, where imported animal clips are mapped onto actor intent names such as idle, walk, run, jump, attack, hurt, and death.

What Is Not Yet True

  • There is no verified dedicated creature shell root in the current source pass.
  • There is no evidence in the inspected files that animal templates have already been re-authored onto ActorShell3D.
  • The existence of shell humanoid scenes should not be rewritten as a finished universal creature framework.

Migration Reading

  • The rewrite direction still points toward component-owned actors.
  • If creatures follow that direction, the likely path is migration from legacy animal NPC scenes toward shell-composed variants, not a separate parallel creature subsystem.
  • That migration is not complete enough yet to be documented as present-day runtime truth.

Validation

  • Recursive checks across engine3d/actors/templates/animals/ show the current animal templates referencing AnimalNPC3D.gd.
  • AnimalNPC3D.gd directly confirms legacy inheritance and clip-to-intent auto-mapping behavior.
  • AGENTS.md and docs/production_rewrite_worklog.md both reinforce that the shell path is the migration target, not the completed actor truth for every family.
