Actor System Overview

Purpose

The Actor System standardizes how interactive entities are defined, initialized, updated, and signaled across the runtime. The interface and core actor classes provide lifecycle hooks and signals used by player and NPC implementations.

Responsibilities

  • Provide a shared actor interface for lifecycle and state management.
  • Expose signals for actor initialization, state changes, tags, and damage.
  • Implement character actors based on CharacterBody3D.
  • Offer concrete scenes for player, NPC, and scenery actors.

Data & interfaces

  • ActorInterface3D (Node): signals actor_initialized, actor_state_changed, actor_tag_added, actor_tag_removed, actor_damaged.
  • Lifecycle methods: initialize, on_actor_ready, on_actor_update, on_actor_physics, on_actor_hit, on_actor_death, on_actor_respawn.
  • State/tag helpers: set_active_state, add_tag, remove_tag.
  • ActorCharacter3D extends CharacterBody3D with movement-related signals (landed, jumped, direction_changed, hurt).

Dependencies

  • Inbound: scene instances of ActorCharacter3D, ActorNPC3D, ActorPlayer3D.
  • Outbound: FSM states and controller modules (see State Machine, Input & Movement).

Debugging & tooling

Actor state changes and tag events are surfaced through the interface signals. Use these signals to trace actor transitions.

Constraints

  • Actor interface hooks should remain consistent across player and NPC implementations.
