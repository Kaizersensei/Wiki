The capability taxonomy is no longer only a handout concept. The current database schema already contains generic capability foundations, but it does not yet expose an actor-specific editor, actor-domain repository, or live capability-authoring workflow.

Core Distinction

  • Category answers what the thing fundamentally is.
  • Capability answers what the thing can do.
  • Runtime state answers what the thing is doing now.
  • Variant answers how this authored form differs from its base record.

That rule still matters, because the current schema is generic enough to support many domains and should not be forced into actor-only semantics too early.

Current Schema Foothold

Table Current role Why it matters here
entitiesGeneric authored record base keyed by entity_id and domain.Actor records would most likely sit here under an actor-like domain instead of requiring a separate first-pass actor table.
capability_definitionsCatalog of capability IDs, display names, domains, and config schemas.This is the first real capability-definition foothold in the live schema.
entity_capabilitiesJoin table enabling or configuring capabilities per entity.This is the concrete relation layer the older wiki wording said did not exist.
record_variantsVariant rows linked to base records.Important because capability deltas belong on variants, not only on base records.
variant_capability_overridesPer-variant capability override layer.Provides the shape for capability additions, removals, or altered config per variant.

Current Limit

Verified now: the schema and variant model already support capability-driven authoring in principle.

Still missing: actor-domain records, capability editors, domain-specific repositories, previews, validation rules, and user-facing workflows.

Safe Current Assumption

  • Do not document actor capabilities as absent from the schema anymore.
  • Do document actor capability authoring as not yet surfaced in the addon UI.
  • Expect the eventual actor workflow to build on generic entities, capability tables, and variant overrides rather than inventing a parallel one-off actor-only model.
