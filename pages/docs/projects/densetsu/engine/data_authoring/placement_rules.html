Placement rules are still mostly planned, but they are no longer floating without context. The repo already has assignment, variant, and compile-shell surfaces that a future rule system would attach to, even though the actual placement-rule schema and evaluation pass have not been migrated yet.

Current Verified Footholds

Surface Current role Why it is still incomplete
map_assignmentsThe live schema can already bind a map_path and domain to a target_id.That links authored scope to a map or Terrain3D target, but it does not encode placement conditions or outputs.
biomesThe current addon has a real biome table and repository count path.Biome records exist, but no generation-rule or topology-binding tables join them to deterministic placement logic yet.
record_variants and override tablesThe authoring DB now has a generalized variant foundation for alternate record definitions.Variants can represent alternate outputs, but they do not decide when or where content is placed.
Terrain, Vegetation, and Compile modulesauthoring_workspace.gd exposes all three as named modules in the hub shell.The current views are scaffolds only: Terrain reports active targets, Vegetation reports sidecar availability, and Compile is still a placeholder entrypoint.

Target Rule Shape Still Comes From Design Docs

Target concern Expected fields or behavior
Identityrule_id, rule-set membership, priority, and enable/disable state.
ConditionsBiome or tag constraints, topology flags, terrain surface bindings, soil, moisture, slope, altitude, and exclusion logic.
Outputsoutput_type, output_id, density, cluster radius, spacing, max-per-chunk, and stable-ID policy inputs.
ExplainabilityA compile pass should be able to explain which rule matched, what evidence it used, and why a placement was skipped.

What Is Still Missing

  • No placement_rules, generation_rules, generation_rule_sets, terrain_bindings, foliage_bindings, or spawn_bindings tables exist in the current migrations.
  • No placement-rule repository, CRUD editor, or validation surface exists in the addon code.
  • No deterministic evaluation pass exists yet that resolves Terrain3D inputs plus authored rules into generated outputs.
  • No operator-facing explain-why or skipped-placement reporting exists beyond the compile-shell placeholder.
  • Because the SQLite backend addon is missing from the repo snapshot, even the existing schema footholds cannot be assumed operational without restoring that dependency.

Safe Current Reading

Verified now: map assignment, biome storage, and generalized variant foundations already exist around the future placement-rule workflow.

Still missing: the actual rule tables, editors, and deterministic rule-evaluation pipeline remain design targets, not live addon features.
