The asset registry is no longer just a target model. The current schema already includes a generalized asset catalog foundation, but the only concrete authoring path writing into it today is still the material-profile sync flow.

Current Foundation

Live Write Path

  1. material_index_service.gd scans the open scene and builds a unique material index with usage counts and paths.
  2. material_profile_repository.gd skips built-in materials and processes only external material resources.
  3. For each external material, the repository calls entity_repository.gd to upsert: entities row: material_profile::<resource_path> asset_registry row: asset::<resource_path> entity_assets link: asset slot material_resource
  4. The same sync pass also writes the domain-specific material_profiles row with class, resource path, usage count, and source scene path.

What The Registry Means Today

  • The project already has a generalized schema for asset tracking across domains.
  • The project does not yet have a generalized asset authoring UI that lets operators browse, edit, validate, or bulk-manage asset records directly.
  • The current registry should therefore be read as a real data foundation with one live ingestion path, not as a finished content-management surface.

Operator touchpointThe Authoring workspace Materials module can refresh the scene index and sync external material profiles into the DB.

Current Limitations

  • No dedicated asset repository class exists yet beyond the generic entity repository helpers.
  • No general asset editor module exists in MODULE_ORDER.
  • No verified live ingestion path exists yet for models, textures, audio, VFX, UI assets, or animation sets.
  • Because the SQLite backend addon is missing from the repo snapshot, the schema and code path are real but cannot be assumed operational without restoring that dependency.

Safe Current Reading

Verified now: the authoring DB already contains a generalized asset-registry schema and a generic entity-to-asset linking layer.

Still missing: a broad asset-management editor and non-material ingestion workflows.
