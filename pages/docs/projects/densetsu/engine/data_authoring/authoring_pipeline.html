The current authoring pipeline is a scaffolded editor shell rather than a full database-first workflow. It establishes module boundaries, scene-view policy, database initialization, and one real sync path for materials. Most domain editors described by the handout are still future implementation work.

Current Operator Flow

  1. Open the Densetsu Authoring main screen registered by plugin.gd.
  2. Refresh scene context so the workspace can detect the active scene, Terrain3D targets, river managers, and tool availability.
  3. Inspect DB status and initialize the schema if the SQLite backend is available.
  4. Switch between scaffold modules such as Biome, Terrain, Vegetation, Water, Materials, and Compile.
  5. Use the Materials module to index scene materials and sync external material profiles into the database.

Scene-Policy Model

Policy field Current meaning
requires_scene_viewWhether the active module expects the live 3D editor context.
interaction_modeCurrent modes are none, camera_only, or camera_pick.
allow_editor_selectionCurrently disabled for all module policies in this slice.
allow_node_transformsCurrently disabled for all module policies in this slice.

The scene bridge is therefore a read-oriented sidecar today. It supports context display and pick reporting, not freeform scene editing.

First Real Migration Foothold

Materials are the first concrete migration slice. The authoring workspace and the legacy material tracker already share the same scene-index backend, and external material profiles can be written into the DB.

This makes the material path the best current example for how future authoring domains should move from ad hoc editor state into project-owned database records.

Current Blockers

  • The SQLite backend dependency is missing from the scanned project tree.
  • No actor, overlay, placement-rule, or generated-record editors are implemented yet.
  • Compile behavior is still a shell, so deterministic generated-content output cannot be verified in this snapshot.
  • Terrain, vegetation, and water modules are context-aware scaffolds rather than full authoring surfaces.
