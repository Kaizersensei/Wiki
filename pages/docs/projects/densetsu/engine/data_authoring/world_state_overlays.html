World-state overlays are still not a finished authoring feature, but they are no longer pure theory. The current schema already contains variant and override tables that can represent altered forms and per-variant changes. What is still missing is the layer that says when those altered forms should become active.

Overlay Versus Variant

Concept Role
VariantThe alternate authored form, such as a burned prop, corrupted creature, or restored state.
OverlayThe authored condition that activates, suppresses, or swaps those variants.
Runtime stateThe live per-instance state or save-state layer, which should not replace authored overlay logic.

Current Schema Foothold

Table Current role Overlay relevance
record_variantsDefines alternate authored forms for a base record.Provides the direct data home for “burned”, “corrupted”, “restored”, or similar alternate forms.
record_variant_overridesStores field-level differences for a variant.Supports targeted swaps instead of full record duplication.
variant_capability_overridesChanges capability relations per variant.Useful when overlays should alter what the active form can do.
variant_asset_overridesChanges linked assets per variant.Useful when overlays should swap models, materials, FX, or other art assets.

What These Foundations Do And Do Not Solve

  • They do solve how alternate forms and override deltas can be represented in schema.
  • They do not solve overlay activation conditions such as story flags, temporal state, environmental triggers, regional ownership, or corruption progression.
  • They do not provide a compile-time resolution pass that explains why one variant won over another.

Current Missing Pieces

Surface Current status
Explicit overlay-condition tablesNot implemented in the current migrations.
Overlay repositoryNot implemented. The addon currently exposes a generic entity repository plus biome and material-profile repositories.
Workspace moduleNo dedicated overlay editor or module exists in MODULE_ORDER.
Compile integrationNot implemented. No verified overlay-aware compile or preview pass exists in the current workspace shell.

Best Current Reading

  • The repo already has the schema shape for alternate forms and delta application.
  • The repo does not yet have the authored condition system that would make those forms into true world-state overlays.
  • Overlay documentation should therefore talk about a real variant foundation plus a missing activation layer, not a fully absent system.

Example Overlay Patterns

Overlay idea What current schema could represent What is still missing
burnedBurned variant assets and capability changes.The condition that decides when a region or object becomes burned.
corruptedCorrupted variants plus capability or asset overrides.The system that activates corruption based on world rules or story state.
occupiedAlternate record forms or support assets.The overlay trigger and compile-time resolution for faction occupation.
restoredRestored variants and rule-facing deltas.The layer that transitions from damaged state to restored state.
