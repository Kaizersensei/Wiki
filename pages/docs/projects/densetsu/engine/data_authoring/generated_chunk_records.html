Generated chunk records are still a planned compile product, not a live database surface. The current repo already fixes the direction, though: SQLite is meant to stay editor-and-compiler authority only, while runtime consumes compiled outputs through catalog and manifest layers instead of querying the authoring database directly.

Current Verified Footholds

Surface Current role Why it is still incomplete
compiler_reportsThe live schema already has a compile-report table with domain, status, summary, and created_at.It stores summary/report rows only, not generated chunk or object data.
map_assignmentsThe addon can already bind authored targets to map paths and domains.This provides compile scope, not generated output storage.

Runtime directionThe design docs consistently require compiled outputs to feed the existing manifest and catalog flow.No current addon code in this slice emits those compiled chunk records yet.

Target Generated Layer

Generated content type Expected identity and storage behavior
Visual filler batchesCan remain compact compiled batch data when the result is purely visual and does not need per-instance gameplay state.
Interactive generated objectsNeed stable IDs, chunk and region provenance, resolved output IDs, transforms, seed data, and mutation flags such as locked, deleted, or converted-to-manual.
Debug and validation provenanceShould preserve the rule, biome, topology, Terrain3D evidence, and seed or chunk context that produced each generated result.

What Is Still Missing

  • No generated_chunk_records, generated_chunks, generated_instance_batches, generated_objects, or generation_seeds tables exist in the current migrations.
  • No compile service, chunk emitter, or generated-output inspector exists in the addon code under addons/densetsu_authoring.
  • No stable-ID writer, per-object provenance trail, or explain-why surface exists yet for generated placements.
  • No current implementation in this slice emits manifest-visible or catalog-visible compiled outputs for runtime consumption.
  • Because the SQLite backend addon is missing from the repo snapshot, even the existing assignment and report footholds cannot be assumed operational without restoring that dependency.
