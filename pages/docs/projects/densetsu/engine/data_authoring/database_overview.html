The Densetsu Authoring database is intended to become the structured knowledge layer for authored game content. Today, the implementation is still a staged build-out: the workspace shell can probe a project-owned SQLite path, run migrations, expose repositories, and report database status, but the full authoring taxonomy from the repo docs is not yet surfaced in schema, repositories, or editor modules.

Current Architecture

Layer Current role Notes
Workspace shellauthoring_workspace.gd shows DB status, module context, and material-sync hooks.Acts as the current operator entry point.
Database serviceauthoring_database_service.gd owns path, backend selection, status refresh, repository creation, and migration execution.Central service boundary for the current addon slice.
Backendsqlite_authoring_database_backend.gd expects the SQLite class from godot-sqlite.Blocked until that dependency is present in the project tree.
Migrationsmigration_runner.gd applies sorted .sql migrations and records versions.Creates a repeatable schema bootstrap path.
RepositoriesBiome, entity, and material-profile repositories are currently implemented.The broader target model still lacks many domain-specific repositories.

Dependency State

Verified blocker: the addon code expects res://addons/godot-sqlite/gdsqlite.gdextension, but that addon is not present in the current project tree.

Effect: the database path, migrations, and service layering are real, but a working SQLite backend cannot be assumed in this snapshot without adding the missing dependency.

Target Model Versus Current Slice

Concern Target model Current slice

Compile modelDeterministic authoring-data to generated-record pipeline with explainable output.Compile shell and report table exist, but the end-to-end compiler remains planned work.
