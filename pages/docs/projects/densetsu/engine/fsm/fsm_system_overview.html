FSM System Overview

Purpose

The FSM System provides deterministic, state-driven behavior for actors. It registers child states, processes updates, and handles transition requests through a central state machine.

Responsibilities

  • Register and manage child states.
  • Dispatch state updates for frame and physics steps.
  • Handle transition requests and log transitions.
  • Expose controller context data to 3D states.

Data & interfaces

  • FSMState (engine/fsm/State.gd): enter_state, exit_state, state_process, state_physics.
  • StateMachine (engine/fsm/StateMachine.gd): register_state, request_state, state_process, state_physics, _log_transition.
  • ControllerContext3D (engine3d/fsm/ControllerContext3D.gd): refresh for runtime context updates.

Dependencies

  • Inbound: actor scripts and controller modules requesting transitions.
  • Outbound: movement/animation states such as AnimIntentState3D, LocomotionAir3D.

Debugging & tooling

StateMachine includes transition logging via _log_transition. Use this to audit unexpected transitions.

Constraints

  • States should implement both process and physics handlers where needed.
  • Transition requests must originate from valid registered states.
