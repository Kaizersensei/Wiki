Autocliff Dock Usage & Troubleshooting

Content status: Operational workflow documented; final screenshot-driven walkthrough is pending UI/foliage overlap resolution.

At a glance

  • Autocliff dock drives slope-based mesh placement on Terrain3D and generic mesh targets.
  • Authoring supports cliffs, foliage, buildings, and other placeables with parameter tuning.
  • Output can be MeshInstance3D for editable instances or MultiMesh for dense population.

How it works

  • Enable plugin, open dock, and select target surface (Terrain3D or mesh-bearing Node3D).
  • Add placeable meshes and configure slope, density, offset, and placement controls.
  • Generate output using the selected mode (individual instances or MultiMesh).
  • For mesh targets, sampling uses triangle ray tests and supports descendant mesh nodes under selected roots.

Interfaces

  • Dock + project plugin integration under res://addons/densetsu_autocliff.
  • Plugin configuration via res://addons/densetsu_autocliff/plugin.cfg.
  • Local reference: res://addons/densetsu_autocliff/README.md.

Operational concerns

  • If instances appear too high/low, validate placeable mesh origins/embedded offsets first.
  • Use MultiMesh for dense output to reduce per-instance overhead.
  • Mesh-target sampling bypasses collision requirements and is useful for imported/temporary geometry.
