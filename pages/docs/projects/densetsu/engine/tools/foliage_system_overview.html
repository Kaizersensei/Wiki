Densetsu Foliage System Overview

Content status: Populated from rewrite notes. User-facing screenshots and asset-authoring standards are pending UI stabilization.

At a glance

  • Densetsu Foliage lives at res://addons/densetsu_foliage and is a project-owned editor plugin plus runtime layer.
  • Purpose: mesh-agnostic foliage painting/erasing/scattering/storage/rebuild on arbitrary mesh surfaces.
  • It does not depend on Terrain3D foliage data and is independent from Autocliff internals.
  • Status: v1 implemented; active rewrite system.

How it works

  • Add/select a DensetsuFoliageLayer3D node and assign/create DensetsuFoliageData.
  • Assign one or more mesh target roots and add foliage types from mesh/scene assets.
  • Use the dock to paint, erase, scatter, rebuild, or clear output.
  • Output is built as scene-owned chunked MultiMesh so it appears in game/export.

Interfaces

  • Plugin/config: res://addons/densetsu_foliage, res://addons/densetsu_foliage/plugin.cfg.
  • Core runtime types: DensetsuFoliageLayer3D, DensetsuFoliageData, DensetsuFoliageType.
  • Sampling/build paths: FoliageSurfaceSampler (no collision requirement), FoliageMultiMeshBuilder (chunked MultiMesh output).
  • Validation gate: res://temp/validate_densetsu_foliage.gd with last documented result DENSETSU_FOLIAGE_VALIDATION_FAILURE_COUNT=0.

Operational concerns

  • V1 scope is static mesh surfaces only.
  • Skinned/deforming meshes and Terrain3D material-ID filtering are currently out of scope.
  • For implementation and design history, use res://docs/production_rewrite_worklog.md and res://docs/foliage.md.
