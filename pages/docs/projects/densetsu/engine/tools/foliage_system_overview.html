At a glance

  • Densetsu Foliage lives at res://addons/densetsu_foliage and is a project-owned editor plugin plus runtime layer.
  • Purpose: mesh-agnostic foliage painting, erasing, scattering, storage, and rebuild on arbitrary mesh surfaces.
  • It does not depend on Terrain3D foliage data and is independent from Autocliff internals.
  • Status: implementation notes are retained, but this page still needs a full current-source verification pass.

How it works

  • Add or select a DensetsuFoliageLayer3D node and assign or create DensetsuFoliageData.
  • Assign one or more mesh target roots and add foliage types from mesh or scene assets.
  • Use the dock to paint, erase, scatter, rebuild, or clear output.
  • Output is built as scene-owned chunked MultiMesh so it appears in game and export.

Interfaces

  • Plugin/config: res://addons/densetsu_foliage and res://addons/densetsu_foliage/plugin.cfg.
  • Core runtime types: DensetsuFoliageLayer3D, DensetsuFoliageData, DensetsuFoliageType.
  • Sampling/build paths: FoliageSurfaceSampler and FoliageMultiMeshBuilder.
  • Validation gate previously referenced: res://temp/validate_densetsu_foliage.gd with last documented result DENSETSU_FOLIAGE_VALIDATION_FAILURE_COUNT=0.

Operational concerns

  • V1 scope is static mesh surfaces only.
  • Skinned or deforming meshes and Terrain3D material-ID filtering are currently out of scope in the retained notes.
  • Implementation details still need to be revalidated against the current addon source before this page can be treated as authoritative for behavior.
