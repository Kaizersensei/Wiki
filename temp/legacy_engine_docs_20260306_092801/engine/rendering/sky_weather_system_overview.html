Sky / Weather System Overview

Purpose

The Densetsu sky/weather system provides a flexible, layered rendering controller for sky color, sun/moon visuals, clouds, fog influence, and weather effects tied to a game clock/calendar and weather sequencing rules.

Design goal

Support a wide range of weather/sky conditions with a parameter-driven system that can be authored per map while still allowing time/calendar-driven automation. The system intentionally favors practical, controllable stylization over strict realism when needed.

Layered sky model (conceptual)

  1. Base sky color: time-of-day driven gradient (24-step/wraparound concept).
  2. Sun layer: visible disc with tunable size/glow/falloff/brightness and light coupling.
  3. Cloud layer group: multiple cloud layers/materials mixed above the sky/sun.
  4. Fog influence: sky/fog blending behavior plus environment-fog integration considerations.
  5. Weather layer: particle systems and weather-specific overlays/behavior.

Clock, calendar, and timeline integration

  • Sky rendering is tied to game time and calendar scaffolding.
  • Weather types can be selected on demand or via a weighted system (conditions/groups).
  • Weather timeline behavior includes duration and blend/transition timing in hours (decimal).
  • Seasonal weighting and grouped weather selection are part of the system direction.

Celestial cycle approach

The current direction is semi-realistic but stylized and gameplay-friendly. Practical examples include explicit visibility windows for the sun, smoother sun/moon transitions, and visual behavior chosen for clarity rather than strict astronomical correctness.

Moon rendering evolved toward a simpler visual model (flat-disc style behavior) when more complex simulation behavior produced undesirable visual artifacts.

Weather system direction

  • Weather definitions can drive particles, fog offsets, and visual shifts.
  • Conditions and grouped weather types support a more authored climate model.
  • Percent-based chance balancing across grouped weather types is part of the design direction.
  • Debug tools are required to make this tunable (weather stack, timeline, forcing weather, timescale).

Debug UI importance

The sky/weather system includes or plans debug UI controls for time, calendar, season, weather forcing, stack inspection, and timeline inspection. Some UI elements are intended to be temporary debug-only controls; others (clock, weather icon) may later become production UI elements.

Known issues / operational notes (tracked deliberately)

  • Fog interactions can visually overpower the sky if blending is not configured correctly.
  • Certain weather transitions (especially foggy conditions) can create white-sky states or abrupt changes if parameters are poorly balanced.
  • Cloud UV wrapping and seams are a current rendering pain point and need explicit handling.
  • Moon material/texture application behavior has required iterative simplification and debugging.
  • Directional light/shadow behavior can break if sun/moon light transitions are not coordinated.

Why failure notes are included

This system was built through intensive iteration. Recording the misbehaviors (snaps, white sky states, seam issues, parameter no-ops, material application confusion) is part of the engineering value, because these are the exact problems future tuning and refactors need to avoid.
