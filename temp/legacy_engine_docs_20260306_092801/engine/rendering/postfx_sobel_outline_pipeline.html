PostFX Sobel Outline Pipeline

Purpose

The Sobel outline pipeline provides a project-compatible screen-space outline pass for stylized rendering, with strong edge detection (including many normal-mapped details) and centralized controls for tuning thickness, threshold, softness, strength, color, and blending.

Why Sobel-first

Multiple outline approaches were tested (including setups that caused severe render-device error spam or incompatibility). The Sobel-based approach reached a stable runtime path and became the preferred foundation for the shader-suite plan.

Pipeline architecture (current direction)

  • Screen-space post-process pass samples rendered scene data and computes edge intensity using Sobel-like gradients.
  • A composite/control node exposes top-level parameters for tuning and debugging.
  • The post-process layer is intended to work with the broader stylized rendering stack rather than forcing per-material outline hacks everywhere.

Runtime vs editor behavior

A key operational lesson: the Sobel effect may appear to do nothing in editor viewports depending on the setup and scene. In the tested setup, the effect was confirmed working at runtime even when editor preview behavior was misleading.

Documentation and QA should always include a runtime verification step before concluding the effect is broken.

Tuning workflow (practical)

  1. Confirm the post-process node is active at runtime and the intended scene/camera path is used.
  2. Use debug edge preview to verify edge detection before color/composite tuning.
  3. Adjust threshold and softness first (edge detection quality).
  4. Adjust thickness/strength next (readability and style).
  5. Tune outline color and blend/mix last (art direction pass).

Separating detection tuning from color/composite tuning avoids many false negatives during setup.

Known failure modes (captured from integration work)

  • Magenta screen / no valid output: shader compile failure or broken pass state.
  • Parameters visible but no visual effect: often a binding/path issue, editor-vs-runtime confusion, or debug mode path not affecting final composite.
  • Black/white inverted output only: debug edge output active or composite path not applying color/mix correctly.
  • Color affects debug but not final: composite stage not using final color path as intended.
  • Strength values above 1 appear capped: output path may be clamped or the effective range saturates; document actual useful range for the current implementation.

Performance / stability notes

  • A stable Sobel pass is preferable to exotic outline systems that destabilize rendering or flood logs.
  • Post-process startup cost and scene-preview cost should be monitored, especially after adding more rendering systems.
  • Centralized controls improve iteration speed and reduce accidental scene-specific breakage.

Planned expansions (tracked separately)

  • Depth-based thickness and distance fade behavior (thicker near camera, thinner/faded far away).
  • Integration with a global toon control layer (without breaking per-material adjustments).
  • Compatibility matrix for third-party shaders and replacements.
